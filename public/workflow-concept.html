Supplier Hub MCP 아이디어 워크플로

Private Label 발주 수정·확정부터 로젠 송장·쉽먼트 문서까지 14개 MCP 역할로 나눈 정적 설계안

CONCEPT · 기능 미연결
Workflow blueprint

자동화 전에, 필요한 역할과 연결 순서부터 그립니다.

Supplier Hub 발주 처리부터 로젠택배 주문·송장 출력, 쉽먼트 문서 출력까지의 업무를 두 구간으로 정리하고 각 단계에 앞으로 만들 MCP 모듈 이름과 구현 아이디어를 배치했습니다. 이 화면에서는 어떤 기능도 실행되지 않습니다.

단계별 MCP 아이디어

모듈명은 기능 계약을 논의하기 위한 가칭입니다.

STEP 01 · 시작점

Supplier Hub 접속

01

로그인된 업무 환경을 열고 Private Label 발주 화면까지 이동합니다.

예상 MCP 모듈 open_supplierhub
향후 구현 아이디어
  • 업무 전용 브라우저 프로필로 Supplier Hub 열기
  • 로그인은 사용자가 직접 하고, 이후 세션은 이어서 사용
  • Private Label 메뉴로 이동하는 동작을 한 모듈로 묶기
이전 단계업무 시작
다음 단계발주 목록 조회 →
STEP 02 · 수집

발주 목록 조회

02

직접 지정한 입고예정일 또는 빠른 조회 기간을 기준으로 Private Label 발주 목록을 가져옵니다.

예상 MCP 모듈 list_private_label_orders
향후 구현 아이디어
  • 입고예정일 시작일·종료일을 입력값으로 받는 조회 도구
  • 발주번호, 발주일, 입고 예정일 등 공통 필드로 정리
  • 화면 연결과 API 연결을 바꿔 끼울 수 있는 구조
이전 단계← Supplier Hub 접속
다음 단계발주 상태 분류 →
STEP 03 · 비교

발주 상태 분류

03

현재 상태와 실행 배정 여부를 기준으로 확정 필요·이미 확정·미처리 재발견·처리 제외를 구분합니다.

예상 MCP 모듈 compare_new_orders
향후 구현 아이디어
  • 거래처확인요청과 발주확정을 서로 다른 후속 경로로 분류
  • 이전 스캔에서 발견됐지만 실행되지 않은 발주는 다시 표시
  • 이미 실행에 배정됐거나 기타 상태인 발주는 사유와 함께 제외
이전 단계← 발주 목록 조회
다음 단계처리 발주 선택 →
STEP 04 · 실행 배정

처리 발주 선택

04

처리 가능한 발주를 하나의 16단계 실행에 배정합니다.

예상 MCP 모듈 select_orders_for_fulfillment
향후 구현 아이디어
  • 신규·미처리 발주 전체 또는 교정용 한 건을 실행에 배정
  • 동일 발주가 여러 실행에 중복 배정되지 않도록 실행 원장 사용
  • 기존 select_orders_for_print는 호환용 별칭으로 유지
이전 단계← 발주 상태 분류
다음 단계확정 양식 다운로드 →
STEP 05 · 확정 양식

발주서 업로드 양식 다운로드

05

거래처확인요청 발주에 사용할 Supplier Hub의 발주서 업로드 양식을 내려받습니다.

예상 MCP 모듈 download_order_confirmation_template
향후 구현 아이디어
  • 확정 대상 발주만 검색하고 선택해 업로드 양식을 다운로드
  • 이미 발주확정 상태인 발주는 이 구간에서 건너뜀
  • 실행별 원본 파일 경로를 후속 엑셀 작성 단계에 전달
이전 단계← 처리 발주 선택
다음 단계확정수량 작성 →
STEP 06 · 엑셀 작성

확정수량 작성

06

선택한 발주 행의 확정수량만 발주수량과 동일하게 작성하고 나머지 셀과 서식은 유지합니다.

예상 MCP 모듈 prepare_order_confirmation_workbook
향후 구현 아이디어
  • 발주번호·발주수량·확정수량 열과 선택 발주 행만 필수 확인
  • 발주수량을 확정수량에 복사하고 일정과 다른 셀은 그대로 유지
  • 첫 실연동은 이 단계의 결과 파일을 확인한 뒤 멈춤
이전 단계← 확정 양식 다운로드
다음 단계업로드·발주확정 →
STEP 07 · 상태 변경

업로드·발주확정

07

현재 상태를 다시 확인한 뒤 준비된 엑셀을 업로드하고 발주확정 상태를 재조회합니다.

예상 MCP 모듈 upload_and_confirm_private_label_orders
향후 구현 아이디어
  • 업로드 직전 이미 확정된 발주는 제외해 중복 변경 방지
  • 업로드 결과가 불명확하면 자동 재업로드하지 않고 중단
  • 최초 교정 완료 후 전체 실행에서는 별도 승인 없이 자동 확정
이전 단계← 확정수량 작성
다음 단계발주서 다운로드 →
STEP 08 · 문서 준비

발주서 다운로드

08

선택한 발주번호에 해당하는 발주서 파일을 내려받습니다.

예상 MCP 모듈 download_order_files
향후 구현 아이디어
  • 선택된 발주번호 목록을 다운로드 요청으로 전달
  • 파일명과 저장 위치를 다음 단계에 넘길 공통 형식 정의
  • 브라우저 다운로드 동작을 독립 모듈로 분리
이전 단계← 업로드·발주확정
다음 단계발주서 인쇄 →
STEP 09 · 출력

발주서 인쇄

09

준비된 발주서 파일을 지정된 프린터로 출력합니다.

예상 MCP 모듈 print_order_files
향후 구현 아이디어
  • 파일 목록, 프린터 이름, 인쇄 부수를 입력값으로 사용
  • 지정된 SINDOH 프린터로 자동 제출하되 불명확한 결과는 재출력하지 않음
  • 인쇄 프로그램과 MCP 도구 사이에 프린터 어댑터 배치
이전 단계← 발주서 다운로드
다음 단계처리 결과 기록 →
STEP 10 · 발주 처리 인계

처리 결과 기록

10

출력된 발주번호와 처리 시각을 남기고, 택배 주문에 필요한 발주 정보를 다음 구간으로 넘깁니다.

예상 MCP 모듈 record_print_result
향후 구현 아이디어
  • 발주번호, 출력 시각, 프린터 이름을 공통 기록 형식으로 정의
  • 다음 신규 발주 비교에서 참고할 수 있는 처리 원장 구성
  • 로젠택배 주문등록에 넘길 상품·수취 정보를 함께 연결
이전 단계← 발주서 인쇄
다음 단계로젠 로그인 →
택배·쉽먼트 처리 구간 발주 처리 결과를 이어받아 로젠 송장을 만들고 Supplier Hub 쉽먼트 문서까지 출력합니다.
STEP 11 · 로젠 인증

로젠 로그인 완료

11

전용 브라우저에서 로젠 로그인을 완료하고 인증된 메인 화면에서 멈춥니다.

예상 MCP 모듈 open_logen_login
향후 구현 아이디어
  • 저장된 전용 Chrome 프로필의 로그인 세션을 재사용
  • 로그인 완료 표시가 준비될 때까지 기다린 뒤 다음 단계에 인계
  • API 연동을 선택한 실행에서는 웹 로그인을 생략
이전 단계← 처리 결과 기록
다음 단계단건 주문등록 화면 이동 →
STEP 12 · 화면 이동

주문등록/출력(단건) 이동

12

예약관리 메뉴에서 주문등록/출력(단건) 화면을 열고 신규 버튼이 보이는 상태에서 멈춥니다.

예상 MCP 모듈 open_logen_single_order_registration
향후 구현 아이디어
  • 로그인 화면으로 돌아가지 않고 인증된 메인 화면을 재사용
  • 예약관리 메뉴와 주문등록/출력(단건) 링크를 순서대로 선택
  • 신규(F3)는 누르지 않고 화면 준비만 확인
이전 단계← 로젠 로그인
다음 단계로젠 주문정보 저장 →
STEP 13 · 택배 접수

신규(F3)·주문정보 입력·저장(F5)

13

준비된 단건 화면에서 신규 주문을 열고 발주·수취 정보를 입력해 저장합니다.

예상 MCP 모듈 register_logen_delivery_order
향후 구현 아이디어
  • 신규(F3) 이후 수하인명·총수량·택배총운임을 입력
  • 센터 수취 정보는 저장값을 우선하고 발주서를 대체 정보로 사용
  • 저장(F5) 결과가 불명확하면 자동 재등록하지 않음
이전 단계← 단건 주문등록 화면 이동
다음 단계로젠 송장 출력 →
STEP 14 · 송장 발행

로젠 송장 출력

14

등록된 로젠 주문의 송장을 전용 송장 프린터로 출력합니다.

예상 MCP 모듈 print_logen_waybill
향후 구현 아이디어

  • 운송장번호와 원송장번호가 함께 있으면 사용자에게 선택 요청
  • 결과가 불명확하면 자동 재출력하지 않음
이전 단계← 로젠 주문정보 저장
다음 단계쉽먼트 송장번호 등록 →
STEP 15 · 시스템 연결

쉽먼트 송장번호 등록

15

예상 MCP 모듈 register_supplierhub_shipment_tracking
향후 구현 아이디어
  • 발주번호로 대상 쉽먼트를 찾고 로젠 운송장번호와 연결
  • 택배사와 송장번호를 Supplier Hub 입력 형식으로 전달
  • 이미 등록된 송장번호는 제외하고 새 번호만 등록
이전 단계← 로젠 송장 출력
다음 단계쉽먼트 문서 출력 →
STEP 16 · 출고 문서

쉽먼트 문서 출력

16

송장번호가 등록된 쉽먼트의 쉽먼트 라벨과 내역서를 출력합니다.

예상 MCP 모듈 print_supplierhub_shipment_documents
향후 구현 아이디어
  • 송장번호가 연결된 쉽먼트를 문서 출력 대상으로 전달
  • 쉽먼트 라벨과 내역서를 하나의 출력 묶음으로 구성
  • 출력 문서 종류와 부수를 MCP 입력값으로 정의

추가 아이디어

기능을 만들기 전에 함께 결정해 둘 설계 주제입니다.

IDEA 01

로젠 연결 경로 선택

기업전용시스템 브라우저 입력과 Open API 등록을 같은 MCP 계약 아래의 서로 다른 어댑터로 둡니다.

IDEA 02

프린터 역할 분리

일반 발주서 프린터, 로젠 송장 프린터, 쉽먼트 문서 프린터를 각각 지정할 수 있게 출력 역할을 나눕니다.

IDEA 03

송장번호를 연결 키로

발주번호, 로젠 주문번호, 송장번호, Supplier Hub 쉽먼트 번호의 대응 관계를 공통 전달 형식으로 정합니다.

IDEA 04

작은 모듈부터 구현

한 번에 전체를 자동화하지 않고, 조회·로젠 주문등록·송장 출력·쉽먼트 등록을 단계별 MCP로 연결합니다.

이 문서의 다음 용도

단계 순서와 모듈 이름을 다듬은 뒤, 구현할 MCP 하나를 골라 입력값과 결과값을 설계합니다.
