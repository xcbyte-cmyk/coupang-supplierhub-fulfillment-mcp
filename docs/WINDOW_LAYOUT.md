# 1~16단계 창 확인과 분할화면 준비

2026-09-17 코드 경로 기준 확인이다. 16단계를 실제 등록·인쇄한 검증을 뜻하지 않는다.

작업 도구의 **분할화면 준비**는 기존 업무 브라우저를 왼쪽에, 열려 있는 관련 작업 창을 오른쪽에 배치한다.
관련 창이 아직 없으면 오른쪽 공간만 준비한다. 여러 작업 창은 오른쪽에 겹쳐 놓는다.
버튼은 로그인, 조회, 배정, 업로드, 등록, 인쇄를 호출하지 않는다.
업무 실행 중이나 검토 대화상자가 열려 있을 때는 버튼을 비활성화한다.

| 단계 | 창/처리 경로 | 배치 방식 |
| --- | --- | --- |
| 1 Supplier Hub 접속 | 세션을 유지하는 Chrome | 접속 시 업무 창과 좌우 배치 |
| 2 발주 조회 | 같은 쿠팡 창 | 기존 배치 사용 |
| 3 상태 분류 | 서버·업무 화면 | 새 창 없음 |
| 4 처리 발주 선택 | 서버·업무 화면 | 새 창 없음 |
| 5 확정 양식 다운로드 | 쿠팡 창과 다운로드 파일 | 파일 다운로드만으로 별도 창을 열지 않음 |
| 6 확정수량 작성 | Python의 XLSX 처리 | 작성 자체는 새 창 없음. 검토에서 파일 열기를 누르면 연결된 Excel 문서 배치 요청 |
| 7 업로드·발주확정 | 업무 검토 대화상자와 쿠팡 창 | 검토 대화상자는 업무 창에 유지 |
| 8 발주서 다운로드 | 쿠팡 창과 다운로드 파일 | 파일 열기 요청 시 연결된 문서 배치 요청 |
| 9 발주서 인쇄 | Excel 인쇄 스크립트 | 백그라운드 인쇄 경로. 인쇄 대화상자는 이동 대상에서 제외 |
| 10 인쇄 결과 기록 | 업무 화면 | 새 창 없음 |
| 11 로젠 로그인 | 로젠 Chrome | 로그인 화면을 열 때 좌우 배치 |
| 12 로젠 주문등록 화면 | 같은 창의 프레임 또는 별도 페이지 | 실제 등록 페이지를 앞으로 가져오며 배치. 프레임은 부모 창에 유지 |
| 13 로젠 주문 저장 | 준비한 로젠 입력 화면 | 기존 배치 사용. 분할 준비 버튼은 저장을 누르지 않음 |
| 14 송장 출력 | 로젠·OZ 출력 화면, Windows 인쇄 대화상자 | 화면 진입 시 배치. 실제 출력 조작 중 창 이동 없음. OZ/Print/인쇄 창 제외 |
| 15 쉽먼트 등록 | 별도 Supplier Hub 세션 | 화면 진입 시 해당 브라우저 창의 CDP 좌우 배치 |
| 16 쉽먼트 문서 출력 | PDF 다운로드·백그라운드 출력 | PDF 뷰어를 자동으로 열지 않음 |

## 범위와 제한

- Windows 창 두 개를 나란히 두는 방식이다. 브라우저 자체의 탭 분할 기능을 조작하지 않는다.
- 업무 페이지가 Windows 창 제목에 표시되어야 찾을 수 있다. Codex 내부 패널처럼 제목을 식별할 수 없으면 일반 브라우저에서 열도록 안내한다.
- 쿠팡·로젠 자동화 프로세스 및 식별 가능한 해당 브라우저 제목을 대상으로 한다.
- 문서는 클라이언트가 전달한 임의 경로를 받지 않고, 선택한 Run의 발주서·준비 문서 기록에서 이름을 얻는다.
- Excel 시작이 느리면 파일 열기 직후 배치가 생략될 수 있다. 창이 열린 뒤 분할화면 준비를 다시 누른다.
- 배치 실패는 업무 등록 성공/실패로 기록하지 않는다. 기존 실행 상태·발주 배정·인쇄 이력은 변경하지 않는다.
- 실제 모니터 배치는 해당 Windows 환경에서 확인해야 한다. 테스트는 요청 계약·오류 안내·빌드와 스크립트 컴파일을 검사한다.

## 이번 확인 결과

- 빌드, Windows PowerShell 구문·C# 컴파일 성공. 관련 테스트 26건 통과.
- 실제 운영 화면에서 작업 도구를 펼쳐 **분할화면 준비** 버튼을 눌렀다.
- 작업을 선택하지 않은 상태에서 업무 창 이동 성공·별도 대상 창 0개 결과가 반환됐고, 화면에 왼쪽 배치·오른쪽 공간 준비 완료 안내가 표시됐다.
- 쿠팡·로젠 로그인이나 1~16단계 업무 실행, 발주 등록·인쇄는 수행하지 않았다. 모든 외부 창을 동시에 띄운 시각 검증은 별도다.
